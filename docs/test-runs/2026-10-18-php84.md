## Initial findings

The original PHP 8.4 installation reached the successful final redirect but failed the empty-body check. Its response contained the `pageDesigner::createTableDetailsBlock()` optional-before-required parameter deprecation. The same diagnostic occurred nine times in that fixture's PHP log. A full definition inventory with `error_reporting=-1` identified the same signature problem in `htmlBlock`, `layout`, and the two global form helpers in `func_html.php`; syntax exit codes alone had not detected these warnings.

## Template and form signatures

`tests/php-signatures.php` failed on the original PHP 8.4 constructor declaration with diagnostics promoted to exceptions, while PHP 7.2 passed. Removed only the ineffective defaults before required parameters in four source files; argument order, names, references, and later defaults remain unchanged. Reviewed existing call sites, which supply the affected arguments.

The focused test then passed on PHP 7.2 and 8.4, exercising constructor argument/reference contracts, detail-table escaping/headings, empty data, and form action/row rendering. A new PHP 8.4 installation completed all 57 functional checks and its final response body was empty. The run correctly remained failing overall because the log contained 1,807 remaining diagnostics, primarily dynamic properties, plus date/cookie/attachment/cron warnings. Those are handled separately.
