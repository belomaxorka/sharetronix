# Baseline defect fixes: 2026-10-18

Follow-up to [the initial baseline](2026-10-18-baseline.md). Checks use Apache 2.4.66, PHP 7.2.34 CGI/FastCGI, MySQL 5.7.44, and synthetic accounts from the local Windows stack unless stated otherwise. Each fix is committed separately with its relevant regression coverage.

## B001: Sessions on non-default ports

Reproduced the original failure by restoring the installer's `DOMAIN=localhost:8092` without changing `SITE_URL`. The ordinary-user login check failed in `scripts/smoke-local.ps1`; the focused session regression also failed before the patch.

`DOMAIN` is used as a URL authority elsewhere in the application, so the fix preserves it. Session cookie names now contain only alphanumeric characters, retain port distinctions, and include a letter even with a numeric installation key and IPv4 host. Cookie-domain attributes derive only the hostname; IPv6 literals use host-only cookies. Existing ordinary-domain session names remain unchanged.

Verification after the patch: `tests/session.php` passed domain, mobile-domain, port, IPv4, IPv6, numeric-key, and port-separation cases; PHP lint passed; all 15 HTTP smoke checks passed with the original port-bearing domain and without the former local domain workaround.

## B002: Loader diagnostics before headers

Before the patch, `tests/autoload.php` failed on the `__autoload()` deprecation, and `tests/response-output.ps1` failed to receive clean compressed application HTML with `E_ALL`, displayed errors, and the outer buffer removed.

The loader now registers its existing core/library lookup through `spl_autoload_register()`. The callback is named `sharetronix_autoload` because PHP reserves and deprecates the former magic function name; class names and lookup paths remain unchanged. The registered callback coexists with previously registered autoloaders.

Verification: the autoload regression passed with warnings promoted to exceptions, the displayed-diagnostics gzip check passed, the session regression and all 15 HTTP smoke checks passed, and the changed PHP files passed lint. Error reporting was not reduced.

## B003: Installer completion after session destruction

The new `tests/installer.ps1` creates a separate site, database, cookie session, and loopback Apache listener on port 8093, sharing only the local FastCGI/database runtimes. It exercises the real five-stage wizard without the development server's `/install/` block. Test data and evidence remain under ignored `.local` and the owned test listener is stopped afterward.

Before the fix, the successful final POST returned HTTP 302 but also rendered 12,757 characters with 26 cleared-session notices. After adding `exit` immediately after the completion redirect, the response body was empty. All eight fresh-installation checks passed, including login with the unmodified generated port-bearing domain. PHP lint and the 15 existing HTTP smoke checks also passed.

## B005: Installed-site update authorization

Extended the isolated installer test to access an installed site with no server-level `/install/` mitigation. Before the patch, the guest GET check failed: the old handler was accessible and ran update cleanup.

Installed-site entry now uses the existing application bootstrap, user session, database wrapper, and CSRF helper. Guests and ordinary users receive HTTP 403. Current administrator status is checked against the database, so cached profile data cannot preserve revoked privileges. An administrator GET displays confirmation without running update cleanup; a session-bound POST token authorizes a bounded update flow. Completion clears that authorization and installer state. The obsolete standalone wizard is disabled; the current entry point remains available for authorized updates.

All 28 installation checks passed: fresh setup, first login, guest GET/POST attempts at all three entry URLs, ordinary-user access, invalid/missing confirmation, revoked administration, authorized update execution, and re-confirmation afterward. A synthetic system-post sentinel proved that denied requests and administrator GETs did not run cleanup, while the confirmed update did. The local Apache mitigation was removed; the 15 HTTP smoke checks then passed against application-level protection. This tests the current-version updater path; migration of older database versions remains unverified.
