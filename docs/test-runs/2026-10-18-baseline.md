## Confirmed defects and follow-up findings

Priorities below are local triage recommendations. No application fixes are included in this environment change.

### B001: Installer includes the port in the session domain

**Priority: P1 — blocks login on a non-default local port.**

1. Install at `http://localhost:8092/` with the generated domain unchanged.
2. Sign in using the correct administrator credentials.
3. Observe a successful login redirect to `/dashboard`, followed by a redirect back to `/signin`.

The generated configuration contains `DOMAIN=localhost:8092`. `my_session_name()` removes dots and hyphens but retains the colon. The emitted cookie name contains `%3A`; the session is not retained on the next request. Setting only `DOMAIN` to `localhost`, while retaining `SITE_URL=http://localhost:8092/`, allowed login immediately.

Relevant code: `install/include/controllers/step_4.php`, `system/helpers/func_main.php` (`my_session_name()` / `cookie_domain()`), and `system/conf_system.php` (session settings). Fix host/port handling and add a session regression check for non-default ports.

### B002: Diagnostic output breaks redirects and compressed responses

**Priority: P1 — functional failure with displayed deprecations.**

1. Run the baseline PHP 7.2 installation with `E_ALL` and browser display of errors enabled.
2. Submit the first installer step without output buffering: the `__autoload()` deprecation is printed before `header()`, and the redirect fails with a headers-already-sent warning.
3. With buffering enabled but diagnostics still displayed, request the installed application using the browser's compressed response negotiation.
4. Observe `net::ERR_CONTENT_DECODING_FAILED`; an identity-encoded response reveals the deprecation before the application HTML.

Relevant code: `system/helpers/func_main.php:3` and the `ob_gzhandler` setup in `system/LOADER.php`. The local stack logs `E_ALL` but keeps browser display off; the deprecated loader remains unchanged. Replace the legacy autoload mechanism and verify clean HTML/JSON/compressed responses as a focused compatibility change.

### B003: Installer renders a template after destroying its session

**Priority: P2 — incorrect control flow and warning output.**

Finish installation and inspect the PHP log. `install/include/controllers/step_5.php` calls `session_unset()` / `session_destroy()`, sets the redirect header, then continues into `loadTemplate('step_5')`. The template reads the cleared `INSTALL_STEP` / `INSTALL_DATA` entries. Both undefined-index notices were observed.

Terminate the successful redirect path and check that a successful finish produces no post-redirect template execution. Do not treat the absence of a visible browser warning as a fix.

### B004: PHP 8.4 cannot parse the current application

**Priority: P1 for modern-PHP support — target runtime is blocked.**

Lint with PHP 8.4.19 using `-n -d short_open_tag=On -l`. The first parse failure in each affected file is an old curly-brace string/array offset:

| File | First failing line |
| --- | --- |
| `system/classes/class_page.php` | 405 |
| `system/helpers/func_main.php` | 261 |
| `system/libraries/securimage/WavFile.php` | 1555 |
| `system/libraries/securimage/securimage.php` | 1920 |

Starting the local web stack with `-PhpVersion 8.4` confirmed HTTP 500 at `/` and the helper parse error. The installer only checks a minimum version number; that check does not establish compatibility. These are initial blockers, not a complete PHP migration inventory. An additional deprecated old-style constructor in `class_Langpack.php` was observed on PHP 7.2 and also needs review during modernization.

### B005: Completed installation leaves the update handler reachable

**Priority: P1 hardening — maintenance actions remain web-accessible.**

After installation, use an independent unauthenticated session to GET `/install/`. The observed response was HTTP 200 with “community has been updated” for 3.6.2. The handler enters update processing without an administrator session. The admin interface does warn that the installation directory should be removed; application-level locking is absent in this flow.

Relevant code: `install/index.php`, `install/include/functions.php` (`get_old_version()`), and `install/include/controllers/update.php`. The tested local web configuration now blocks `/install/` after restart. Add an explicit installation/update authorization or locking mechanism before a deployable maintenance release. This observation does not establish that a fresh reinstall or credential disclosure is possible.

### B006: Cron temporary-file cleanup fails despite successful exit

**Priority: P2 — background maintenance does not complete cleanly.**

Run the local copy of `system/cronjobs/worker.php` with PHP 7.2 and the local `php.ini`. The process exits 0, but `php_6h/2-clean_temp_dir.php:3` reads an undefined `$C->TMP_DIR`; `opendir()` does not yield a directory resource, and `readdir()` warns at line 5. The temporary-directory cleanup therefore did not succeed.

Define a consistent temporary-directory contract and add an observable failure result for failed background jobs. Verify the relevant directory exists inside the installation before executing cleanup.

### Additional finding: Legacy external version check in cron

`system/cronjobs/php_6h/7-clean_request_tokens.php` performs an unconditional cURL request to the former developer site's version-check URL, including version, site URL, and language. The code has no request timeout and is not controlled by `RPC_PINGS_ON`. The worker reached this file during the check; remote service functionality and delivery were not established. Stub or remove this retired dependency deliberately before enabling scheduled runs. No recurring task was created.
