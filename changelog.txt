Sharetronix 3.6.3 (unreleased)
	Security:
	* Restricted post attachment uploads to an allowlisted set of extensions, required an
	  authenticated session for the attachment service, and stored uploads under a single safe
	  extension derived server-side. This closes an unauthenticated remote code execution path where
	  a guest could upload a .php file into the web-served storage/ tree and execute it on PHP-FPM
	  or AllowOverride None servers, and the equivalent extension-controlled path in the API.
	  Rejected .svg and other active-markup uploads that could run as same-origin script. The
	  allowlist is configurable through $C->ATTACH_ALLOWED_EXTENSIONS.
	* Hardened storage/.htaccess to deny direct execution and serving of scripts and active markup
	  (including .svg, .phar, .phtml) regardless of the handler, covering PHP-FPM deployments where
	  the previous RemoveHandler directives had no effect. Reduced uploaded temporary-file
	  permissions from world-writable to 0644.
	* Rejected missing or malformed Twitter account ids before looking up a linked account. Accounts
	  that never linked Twitter store an empty twitter_uid, so a failed or empty Twitter profile
	  response previously matched the first such account (normally the administrator) and signed the
	  visitor in without a password. Lookups now accept only numeric ids, escape them, and the
	  Twitter callback stops when no profile id is returned.
	* Required network-administrator or group-administrator rights to remove a group moderator. The
	  removemoderator service previously called group::deleteAdmin() with no caller check, so any
	  guest or ordinary user could strip administrators from any group (down to its last admin). The
	  handler now rejects callers who are neither a network administrator nor an administrator of
	  the target group.
	* Stored the display name HTML-escaped on every path that writes it. Self-registration,
	  including the Facebook and Twitter callbacks, saved fullname raw while profile pages, menus,
	  feeds and @mention rendering print it unescaped, so a visitor could register a name containing
	  markup and run script in the browser of anyone viewing their profile or a post mentioning
	  them. The signup form now escapes the name exactly like the settings and API paths already did
	  and no longer echoes a raw name back into the registration form; the installer escapes the
	  administrator's name the same way. The 3.6.3 updater entry rewrites names that earlier
	  registrations stored raw, leaves already-escaped names unchanged, and can be repeated safely.
	* Escaped attachment file names where they are shown. A file keeps the name its uploader gave
	  it (the browser's file name, or the file_type of the API statuses/update), and the post view
	  printed it unescaped in the download link, so a file named, for example,
	  qa<img src=x onerror=...>.txt ran script in the browser of everyone who saw the post. The
	  upload answer that the post form shows as a preview now escapes the name too.
	* Stopped printing the server's storage path into pages. getAvatarUrl() echoed the absolute
	  path of a missing avatar thumbnail (a debug statement left since 3.0.1) before creating the
	  thumbnail, so visitors of a page showing that avatar saw where the site is installed.
	* Stopped the public /cron page from showing PHP errors and the job list to visitors. The cron
	  worker turned display_errors on for every run, and /cron discarded the worker's output only
	  when it finished, so an error in any background job, including plugin jobs, sent the error
	  message with the full file paths and stack trace to whoever requested /cron, even on servers
	  configured not to display errors. The worker now enables error display only on the command
	  line, and /cron discards the worker's output in all cases; errors are still logged.
	* Escaped the SQL queries and cache keys shown in the debug console. They were written into the
	  console window as HTML, and the window runs with the site's origin, so a crafted link (for
	  example a search term containing markup) could run script with the session of a developer
	  whose address is in $C->DEBUG_USERS and who had the console enabled.
	* After the update had been confirmed, the following updater forms were accepted without a token
	  for 30 minutes, so another site could submit the update step on behalf of a signed-in
	  administrator. Every form of an update now carries the confirmation token.
	* Pages and services of a plugin answered as soon as its directory existed in apps/, also when
	  the plugin was not installed or had been uninstalled: any signed-in user could open its pages
	  (for example the maintenance settings page) and any visitor could call its services. Only
	  installed plugins answer now.
	* The plugin actions of the administration were links without a token that took a filesystem
	  path from the address, ran the installer.php found there and, on uninstall, deleted that
	  directory with everything in it; a page on another site could make a signed-in administrator
	  follow them. They are now forms with a token and accept only the name of a plugin folder in
	  apps/.
	* With marketplace credentials saved, every page of the administration sent them to the
	  marketplace over plain HTTP (the password as an unsalted md5) to count language updates. The
	  administration no longer contacts the marketplace for languages.
	* The installer left the root .htaccess file writable by every user of the server (mode 0777)
	  and changed the permissions of files and folders one level above the installation directory.
	  When the web server could not write to a folder it needs, the installer and the updater made
	  the folder writable by everyone; they now add read and write permission for its owner only.
	* The "Get New" tab of the themes page confirmed the removal of a theme through a plain link,
	  without a token, that carried a path on the server. A crafted link opened by a signed-in
	  administrator could delete any folder the web server can write to that holds a theme manifest,
	  such as themes/default. The tab is removed.
	* Installations that had used the plugins or languages page of 3.0 to 3.6.2 kept the marketplace
	  credentials it saved in the settings table, the password as an unsalted md5. The 3.6.3 update
	  deletes them; nothing reads them any more.
	* Every visit to the general settings page sent the site's address to developer.sharetronix.com
	  over plain HTTP to check for updates, and the page showed the answer as HTML. That host no
	  longer exists; whoever answered in its place, or anyone on the network path, could put HTML
	  and scripts into the administration panel. The check is removed.
	* Sign-up and password recovery remove the CAPTCHA code after every check, so a wrong answer no
	  longer leaves the same code open to further guesses; codes have five characters instead of
	  three.
	* The contact form uses the shared image CAPTCHA of sign-up and password recovery. Its own
	  CAPTCHA showed one fixed GIF image per character, so a script could read the code from the
	  file hashes, and a key and word that passed once stayed valid for the rest of the session.
	* Avatars, logos, favicons, attachment images and copied files were made writable by every
	  account on the server (mode 0777), and so were the entries of the file cache, which the
	  application reads back with unserialize(); on a server shared with other accounts they could
	  be replaced. Files now get mode 0644 and cache entries 0600. The installer no longer makes the
	  attachment folder writable by everyone.
	* Turned off the NO_BACKSLASH_ESCAPES SQL mode for the application's database connections. In
	  that mode the escaping function only doubles single quotes, while the queries put values in
	  double quotes, so on a server configured with it a double quote in any input ended the string
	  and changed the query.

	Fixed:
	* Redirected signed-in users returning from the Twitter callback without a linked account
	  through the page object instead of an undefined $this, which previously caused a fatal error.
	* Corrected template and form signatures with optional parameters before required arguments,
	  keeping their existing positional/reference contracts on PHP 8.4.
	* Declared existing runtime properties in core, rendering, activity, and notification classes to
	  avoid PHP 8.2+ dynamic-property diagnostics while preserving public state and serialized
	  references.
	* Kept all-error reporting enabled without referencing the deprecated E_STRICT constant.
	* Used an empty string when clearing persistent-login cookies, preserving logout and
	  invalid-cookie rejection without PHP null-argument deprecations.
	* Preserved the saved post type before converting its ID to an integer in activity responses,
	  selecting the correct public/private table without array-offset warnings.
	* Rendered the profile month selector through the shared date formatter instead of calling
	  deprecated strftime() directly, retaining all twelve labels.
	* Initialized language-package metadata through __construct() on PHP 8 while retaining explicit
	  calls to the legacy initializer.
	* Replaced the removed create_function() callbacks in post, comment, and FAQ link rendering with
	  closures, retaining link markup, punctuation, and escaping. Comments containing links, the
	  posts and profiles that display them, and the FAQ page no longer fail on PHP 8.
	* Rendered older-post and profile-information dates through a shared formatter: PHP 7.2–8.0 keep
	  native, locale-aware strftime() output for language packs, while PHP 8.1+ uses the bundled
	  English percent formats and PHP timezone without the deprecated function.
	* Declared the feed polling cursor used by background activity checks, removing a PHP 8.4
	  warning observed in the browser.
	* Restored administrator plugin/language controller initialization on PHP 8 while preserving
	  legacy initializer calls and reference arguments.
	* Restored plugin-installer option, adapter, validation-message, and singleton initialization on
	  PHP 8 without changing their legacy method entry points.
	* Added modern constructors to the bundled XML-RPC library while retaining its legacy
	  initializers and request-serialization behavior.
	* Retained login sessions on non-default ports while preserving URL authorities and existing
	  session names for ordinary domains.
	* Registered the existing class-loading behavior through SPL to prevent autoload deprecations
	  from corrupting headers and compressed responses.
	* Stopped installer execution immediately after the successful completion redirect, avoiding
	  reads from the destroyed installer session.
	* Required an active administrator and session-bound confirmation before installed-site updates;
	  disabled the obsolete installer entry point.
	* Defined the private temporary-directory path and corrected cron cleanup for expired files,
	  including filenames equal to zero.
	* Corrected request-token expiry to use the existing database column, allowing cron processing
	  to continue past token cleanup.
	* Replaced removed curly-brace string offsets in core redirects/password generation and bundled
	  CAPTCHA/audio code, restoring PHP 8.4 parsing.
	* Removed a daily-maintenance query against the deleted RSS table, allowing database
	  optimization to complete with the current schema.
	* Corrected daily temporary-file cleanup to use the private directory rather than the worker's
	  current directory, preserving placeholders and subdirectories.
	* Completed cron intervals without core job directories, including their plugin jobs and
	  running-flag reset.
	* Declared the Windows strptime() replacement only when PHP lacks the function, so the file no
	  longer fails to compile on its own where strptime() is built in.
	* Rendered https-only links in posts and comments. The rendering guard tested for http:// twice
	  and never for https://, so a message whose only links were https stayed plain text.
	* Kept the space before a bare link in FAQ text instead of gluing the link to the previous word.
	* Imported the current user in setCachedHTML(), which built per-user cache filenames without
	  it. Per-user entries were written under an empty user id, never found again by their owner,
	  and served to guests, whose id is also empty; each write raised an undefined-variable
	  warning. Only plugins use per-user caching. After upgrading, clear system/cache_html/ to drop
	  entries written the old way.
	* Shortened long link text in posts and comments on character boundaries. It was cut by bytes,
	  so a long non-ASCII address produced invalid UTF-8: the post was saved but its response
	  reported an error, inviting a duplicate, the comment response came back empty, and feed pages
	  containing the post failed to load.
	* Kept smileys out of links and character entities in posts and comments. A smiley code inside a
	  URL, such as :P in /wiki/Help:Pages, was replaced inside the link and broke it, and text such
	  as ("quoted") lost its closing quote to a wink, because the escaped &quot;) contains ;). On
	  PHP 8.1 and later the same happened to an apostrophe before a closing parenthesis.
	* Recognized links whose scheme is written in capitals, such as HTTPS://, in posts and comments;
	  the link pattern already ignored case, but the check in front of it did not.
	* Kept https:// addresses in the group settings menu. On HTTPS sites its Invite and Settings
	  links pointed to http://https://...
	* Built RSS avatar addresses from the storage URL. The feed read the $C->IMG_URL setting, which
	  no longer exists, so avatar images had no host and each entry logged an undefined-property
	  warning.
	* Declared pageDesignerMobile::$system_files, removing a PHP 8.2+ dynamic-property deprecation
	  on mobile pages.
	* Read file-cache entries whose value contains a line break. The file cache accepted an entry
	  only if the file had exactly two lines, so every value with a line break (for example a user
	  whose profile text has several lines) was treated as a miss, deleted and queried again on
	  each request. del() now also returns its result outside debug mode.
	* Used the cached group id when a group is looked up by name. The check compared the cached id
	  with TRUE instead of testing $force_refresh, so the cache was written on every lookup but
	  never read, and every group URL cost an extra query. Deleting a group now also forgets its
	  name.
	* Declared the extension-name property of the memcached cache driver, removing the PHP 8.2+
	  "Creation of dynamic property" deprecation logged on every request and cron run that used
	  memcached.
	* Passed integers to rand() when the HTTP cron reschedules jobs stuck for more than six hours.
	  rand(0.5, 1.5) already behaved as rand(0, 1), but logged two "Implicit conversion from float"
	  deprecations per job on PHP 8.1+.
	* Refreshed the cached list of private groups when a group is made public. Only the change to
	  private refreshed it, so posts of a group that had just become public stayed hidden from
	  feeds and search for non-members until the cache expired (one hour by default).
	* Refreshed the cached author and group after a post is published or deleted, so profile and
	  group post counts no longer lag behind for up to an hour.
	* Listed every attachment of a post in RSS feeds. Posts keep a list of attachments per type,
	  but the feed read each type as a single object, so no link, file, image or video has appeared
	  in an entry since 3.x, and every such post logged several warnings per feed request. File
	  links now use the getfile/pid:.../attid:N route of the web feed instead of the file title, and
	  images and video thumbnails come from the storage URL instead of the removed $C->IMG_URL
	  setting.
	* Kept a custom header logo when an administrator switches the theme. The switch looked for
	  the logo files under $C->IMG_DIR, which 3.x no longer defines, so the logo was never found
	  and the site fell back to the default logo; the files are now read and written under the
	  storage directory. The logo resized for the new theme is remembered for that theme instead of
	  under a setting named after the file, and a theme without a logo height still falls back to
	  the default logo.
	* Deleted the old avatar files when the API replaces an avatar (account/update_profile_image).
	  The handler removed them under $C->IMG_DIR, which 3.x no longer defines, and skipped two of
	  the five thumbnail sizes; it now removes all of them from the storage directory, like the
	  avatar settings page. The account API itself still stops earlier, because it requires the
	  missing classes/class_rssfeed.php.
	* Made installation and updates through /install/ work over HTTPS. The mod_rewrite check always
	  requested its test files over http://, so on an HTTPS-only site it reported "mod_rewrite:
	  FAIL" and offered no button to continue, and the wizard always saved an http:// site address
	  in system/conf_main.php. Both now use the scheme of the current request. The check skips
	  certificate verification for this request to the server itself, so self-signed certificates
	  work, uses cURL when it is available, and when the server cannot reach its own address it
	  shows a warning and lets the installation continue instead of failing.
	* Showed guests a sign-in entry in the mobile menu instead of the account menu. For a visitor
	  who is not signed in, the menu read the username, name, avatar and position of a missing
	  account, logging seven warnings on every mobile page, and offered profile, dashboard and
	  "Sign out" links; like the desktop header, it now offers the mobile sign-in page.
	* Made the account API (/1/account/*: verify_credentials, update_profile, update_profile_image,
	  rate_limit_status, end_session) answer again. Since 3.0.1 its controller required
	  classes/class_rssfeed.php, which was removed together with the RSS feed reader, so every
	  account request stopped with a fatal error before authentication. The other API resources were
	  not affected.
	* Answered 404 for the account API resources create, destroy, exists, show, incoming and
	  outgoing, which were listed as available but never implemented in 3.x and answered an empty
	  200.
	* Saved a changed website through the account API (update_profile url) when the user already
	  had one. The update addressed an undefined variable, so it changed no row, answered 304 and
	  logged a notice or warning; only the very first website was ever stored.
	* Answered account API profile updates (update_profile) with the updated profile. The cached
	  user was refreshed only after the answer had been built from it, so clients received the
	  values from before the change.
	* Linked API user avatars (profile_image_url) to the storage directory. The API still built them
	  from the 2.x upload directory i/, which 3.x no longer has, so the link answered an HTML page
	  instead of the image.
	* Reported the API rate limit again (account/rate_limit_status). It read $C->rate_limit_number,
	  whose default of 150 was commented out in 3.x, so the answer had an empty hourly limit and
	  each request logged undefined-property notices or warnings. Requests are still not limited.
	* Answered account API sign-outs (end_session) with valid JSON, {"logout": true}. The JSON
	  answer was "logout": true, which JSON clients cannot parse. The XML answer is unchanged.
	* Stopped the account API from logging PHP warnings and deprecations: update_profile_image read
	  an unset error flag after a successful upload, end_session created a dynamic property, and the
	  "API is disabled" answer read undefined variables, so it was always XML. That answer now uses
	  the requested format.
	* Answered "API is disabled" in the requested format and JSONP callback in the other API
	  resources too (statuses, users, friendships, groups and the rest). With the API switched off
	  and suppress_response_codes set, they read undefined variables, so the answer was always XML
	  and PHP warnings were logged.
	* Made API error answers (requested with suppress_response_codes) parseable. JSON errors were
	  "hash":{...} without the enclosing object and are now {"request": ..., "error": ...}, the
	  shape of Twitter API v1 errors. XML, RSS and Atom errors escape the request URI, so a second
	  query parameter no longer breaks them; the Atom error closes its <item>, and the RSS and Atom
	  links use the site URL instead of http://http://....
	* Fixed birthdate updates through the account API (update_profile): the date check called
	  split(), which PHP 7 removed, so any request with a birthdate stopped with a fatal error. Its
	  error message now names the format the check accepts, YYYY-MM-DD (it said YYYY-DD-MM).
	* Answered ERROR to activity feed requests (services/activities/checknew, getnew and getall)
	  with an unknown activities_type instead of stopping with a fatal error. The activity factory
	  no longer lists the type "view", whose class activityView never existed in any 3.x release.
	* Offered attachment downloads under the name they were uploaded with again, as 2.x did. Since
	  3.0.1 they were saved under the random stored name (for example 1729341234123456.pdf). Names
	  that are not plain ASCII, such as Cyrillic ones, are sent in the RFC 6266 filename* form.
	* Took the header logo height from the active theme. Administration > Branding resized an
	  uploaded logo to a fixed 80 pixels, and the default theme's manifest asked for 34 (a 2.x
	  value) although the 3.x layout reserves 80, so switching back to it shrank the logo. Both now
	  use the theme's logo_height, or 80 when the theme sets none; switching to such a theme used
	  to drop the custom logo. Logos resized before keep their size until they are uploaded again.
	* Included only the .js and .css files of a theme's js/ and css/ folders (and of a plugin's
	  static/js/ and static/css/) in pages. Every entry was added as a script or stylesheet, so
	  pages also linked subfolders such as js/mobile/ of the 3.x theme packages, notes and hidden
	  files.
	* Shortened long link text in posts and comments as it is displayed. The text was measured and
	  cut in its HTML-escaped form, so &amp; counted as five characters and a cut could fall inside
	  an entity, leaving fragments such as "&amp" or "p;b=2" in the post.
	* Kept the Leave item of the group settings menu as a script link (href="#"). The menu prefixed
	  it with http:// and opened it in a new window like an off-site link, so opening it in a new
	  tab, or without JavaScript, led to the invalid address http://#.
	* Named per-user HTML cache files (getCachedHTML() and setCachedHTML() with a user id) without
	  ":" (current_user_<id>-about_user_<id>). Windows does not allow ":" in file names, so these
	  entries were never stored there. setCachedHTML() also returns FALSE when the cache file cannot
	  be written instead of always reporting success.
	* Left a theme's scripts out of mobile pages, as its stylesheets already were. Mobile pages
	  linked them under the mobile address (/m/themes/...), which is no file, so each script tag was
	  answered with a redirect to the mobile dashboard: with a 3.x theme package, one mobile page
	  view cost 15 more page renders and loaded none of the scripts. Sites serving mobile pages from
	  an m. subdomain loaded the desktop theme scripts there; they no longer do.
	* Wrote valid JSON for API answers that carry a text with a line break, a tab, a backslash or
	  a quote: account/verify_credentials (it includes the user's latest post), the status
	  timelines and every other answer that TwitterData builds. Such values were only HTML-escaped,
	  so a single multi-line post made the whole answer unparseable. Ordinary text is unchanged.
	* Recounted the posts of users with more than 1000 posts on sites without private groups. The 6h
	  cron job built "NOT IN()" from the empty list of private groups, MySQL rejected the query, and
	  the worker stopped there: the remaining 6h jobs and the 24h jobs (table optimization, removal
	  of old notifications and request tokens, clearing of the cached page HTML and temporary files)
	  did not run while such a user existed, and their running flags stayed set. On PHP 7 this
	  happened without a log entry.
	* Handled database errors the same way on every PHP version. On PHP 7 a failed connection or
	  query ended the request with an empty page, HTTP 200 and nothing in the log. Since PHP 8.1,
	  where mysqli throws exceptions by default, the same failure ended in an uncaught
	  mysqli_sql_exception instead, which servers that display errors showed with a stack trace,
	  file paths and the database user. The database layer now turns mysqli exceptions off, answers
	  HTTP 500, logs one line with the MySQL error, the start of the query and the calling file, and
	  exits with status 1, so a failed cron run is visible to the cron daemon. Debug mode still
	  shows the query and the error, now HTML-escaped.
	* Restored the "Cannot connect" and "Database does not exist" messages of installer step 2 on
	  PHP 8.1+. A wrong database password or name showed a fatal error with a stack trace instead.
	* Kept a higher or unlimited PHP memory limit in the cron worker. The worker set memory_limit to
	  64 MB on every run, which lowered the 128 MB default and any larger server setting; it now
	  only raises a lower limit to 64 MB.
	* Removed leftover debugging code from the plugin administration page (/admin/plugins). It
	  turned on the display of all PHP errors for every administrator who opened it, regardless of
	  debug mode, and declared a global function p(), which made the page fail if a plugin or theme
	  declared a function with that name.
	* Removed a leftover var_dump() from the service that attaches a group to a new post
	  (services/attachments/setgroup). It answered with a dump of all attachment drafts of the
	  session instead of JSON. The editor now handles the answer with its own callback; before, it
	  reused the group check callback, which would have sent the request a second time without a
	  group.
	* Logged failed e-mail deliveries. do_send_mail() and do_send_mail_html() ignored the result of
	  PHPMailer, whose mail() call suppresses PHP warnings, and always returned TRUE, so signup and
	  password recovery mails, e-mail changes, invitations and notifications could fail without any
	  trace. A failed delivery now writes one line to the PHP error log with the mailer error, the
	  recipient's domain and the subject, and both functions return FALSE. Pages still show their
	  usual confirmation.
	* Checked for a missing user or group id in the follow, unfollow, join and leave services. Such
	  requests logged an "Undefined array key" warning; in debug mode the printed warning came
	  before the "ERROR" answer, so the service reported status "OK".
	* Showed an error message when a service request fails. When a service answered with an error
	  status or an empty body, for example after a database error, the shared service script passed
	  undefined data to the page's handlers, which then failed with a JavaScript error: posting,
	  commenting, liking and following silently did nothing. The handlers now receive a failure with
	  the message "The request failed. Please try again.", on the desktop and mobile pages; the link
	  attachment handler shows it too instead of an undefined text.
	* Accepted any value of $C->DEBUG_USERS in system/conf_main.php. A single address written as a
	  string, an empty string or a missing setting made every request fail with a TypeError on PHP 8
	  (HTTP 500 for the whole site) and logged a warning on PHP 7. A string is now read as one
	  address, and addresses must match exactly, so a listed TRUE no longer turns debug mode on for
	  everyone.
	* Made the debug console usable. $C->DEBUG_CONSOLE = TRUE; in system/conf_main.php now enables
	  it for debug mode (system/conf_system.php used to reset the setting to FALSE), and the console
	  opens from a small "Debug" link at the bottom right of the page, because browsers block the
	  window it used to open by itself when the page loaded. The console window also renders in
	  standards mode and no longer shows an empty "Assigned template variables" section.
	* Kept the hourly file cache cleanup running when an entry disappears during the scan. Requests
	  delete expired entries themselves, so the cleanup could list a file that was gone when it
	  opened it; on PHP 8 this stopped the cron run with a TypeError and left its running flag set.
	  The cleanup now skips such entries, returns when the cache directory cannot be opened, and
	  closes the directory.
	* Corrected the cache statistics of the debug console. The file cache recorded an extra DELETE
	  entry for every write and for every expired read and counted that time twice, so the console
	  showed half again as many cache operations and a total time above the real one. All drivers
	  also listed a hit on a stored empty value (an empty list, 0 or an empty string) as FALSE, like
	  a miss.
	* Let the plugin installer connect to the database on PHP 8. Its database layer ran "SET
	  CHARACTER SET UTF-8", which MySQL rejects; PHP 7 ignored the error, but PDO reports errors as
	  exceptions since PHP 8.0, so installing or removing a plugin whose installer changes the
	  database stopped with "Error connecting database!". The connection still uses utf8 through SET
	  NAMES.
	* Buffered the compressed page output until the end of the request. system/LOADER.php passed 6
	  as the second argument of ob_start('ob_gzhandler'), which is a chunk size, not a compression
	  level: the buffer was flushed after every 6 bytes of output, so on servers with
	  output_buffering off any early output, such as a notice shown in debug mode, sent the headers
	  at once and later redirects and cookies were lost. The compression level still comes from
	  zlib.output_compression_level.
	* Reported service answers that cannot be encoded as JSON. When an answer contained invalid
	  UTF-8, the services page sent an empty body with HTTP 200 and logged nothing; it now answers
	  HTTP 500, so the page shows its error message, and logs the service name and the JSON error.
	* Kept command-line cron runs out of debug mode. The cron worker set the client address to
	  127.0.0.1 before the debug check, so a development configuration listing 127.0.0.1 in
	  $C->DEBUG_USERS ran every cron job in debug mode: all query texts stayed in memory and failed
	  queries printed their SQL to the cron output. The worker now sets the address after the check;
	  jobs still see 127.0.0.1.
	* Limited the memory used by the debug query log. In debug mode the database layer kept the text
	  and time of every query until the end of the request, about 600 bytes per query (27-30 MB for
	  50,000 queries), so long requests could run out of memory. It still counts and times every
	  query, but keeps the text of the first 1000 only; the debug console shows the full number and
	  how many are listed.
	* Logged unreachable memcached and Redis servers. Both drivers fall back to running without the
	  cache, but did so silently: the memcached driver even recorded "CONNECT TRUE" in the debug
	  console, because adding a server does not connect to it. A request that cannot use the cache
	  server now logs one line with the server and the error, and the debug console shows the
	  failure. The legacy memcache extension already reported such failures as PHP notices and is
	  unchanged.
